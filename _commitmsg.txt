Fix two data-pipeline defects found by external review; add paper skeleton

外部 review 逐行审查了脚本并重跑验证，指出两个**真实的实现缺陷**。本次修复
并重新生成全部产物，同时同步所有文档与论文中的数字。

== 缺陷 1：Dialect 目录归属静默丢失 235 个文件（严重） ==
collect_corpus 的 camel_to_ns() 对 test/Dialect/<Name> 做驼峰切分，得到错误命名
空间，analyze.py 又不告警，导致整批文件从"投入分布"里消失：
  LLVMIR(86)        -> "llvmir"        应为 llvm
  SparseTensor(122) -> "sparsetensor"  应为 sparse_tensor
  X86(19)           -> "x"             应为 x86
  MLProgram(6)      -> "mlprogram"     应为 ml_program
另有 2 个 test/Dialect/ 直下的单文件被当成方言目录。

修复：在 layers.json 的 aliases 里补 8 个别名，2 个单文件归入 noise。
后果（已同步进 docs/04、08 与论文表 2）：
  各层投入 259/235/232/222/56/73 -> 364/354/235/222/62/73 + 基础设施 80
  导入层占比 5.2% -> 4.5%；已归属文件 1,077 -> 1,390
  **发现 3 的叙事随之重写**：不再是"四个中后段层几乎均匀"，而是明显两级
  （目标 26.2%、张量 25.5% | 并行 16.9%、存储 16.0% | 导入 4.5%）。
  主论点（栈顶投入显著最低）反而更强：4.5% vs 16–26%。

== 缺陷 2：Conversion 目录名被贪婪切分出 7 条伪边 ==
GPUToLLVMSPV / ArithAndMathToAPFloat / ComplexToLibm / MathToLibm /
ComplexToROCDLLibraryCalls / TosaToMLProgram / VectorToAMX 被解析成
llvmspv / apfloat / libm / rocdllibrarycalls / amx / mlprogram 等假方言。

修复：再补 8 个别名（LLVMSPV->llvm、Libm->func、ROCDLLibraryCalls->rocdl、
AMX->x86 等）+ 1 条 conversion_overrides（ArithAndMathToAPFloat 两端不定）。
注意：修正方式是**重新归属**而非删除，故 |E| 78 -> **76**（review 估计的 71
偏保守，多数伪边对应真实转换，只是名字解析错了）。
连锁：M 由 10 -> **11**（x86 进入目标集），工程级 N* 17.6 -> **15.5**，
架构级 N* 4.8 -> **4.6**，最深层占比 79.0% -> **79.2%**（236/298）。
