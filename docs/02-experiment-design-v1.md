## 1. 三个假设与**证伪判据**

写报告时，假设必须带可检验的判据，否则只是叙述。

**H1（收敛性）**：层间转换在栈底收敛。
- 支持：落到 `target` 层的边占比 ≥ 0.5，且 `target` 的入度为各层最高。
- 反驳：入度在中间层（`tensor` / `memory_vector`）更高，说明边界不在栈底。

**H2（不对称性）**：复用集中在低层，靠近框架的一端仍然碎片化。
- 支持：`frontend` 层的出边只指向极少数下游层，且 `frontend` 相关方言的跨项目共享度显著低于 `llvm` / `arith`。
- 反驳：各层入度/出度分布近似均匀，说明"分层"在每段都同等有效。

**H3（条件性）**：收益取决于共享层采纳率 p，不是无条件成立。
- 支持：当 p ≤ 1/M 时，交叉点 N\* 无解或远超现实框架数量（即分层方案永不占优）。
- 反驳：即使 p 很低，N\* 仍远小于现实规模。

> 三个假设里 **H3 是全文的支点**，因为它把"MLIR 很好"这种不可证伪的说法换成了一个带参数的命题。写成"若 p 低于 1/M 则……"这种形式，评阅人无法说你在宣传。

## 2. 指标定义（写进报告的方法节）

| 指标 | 定义 | 为什么可用 | 已知偏差 |
|---|---|---|---|
| 层间边 `(u→v)` | `test/Conversion/<X>To<Y>/` 目录对应的方言对，按 `layers.json` 聚合到层 | 目录名即 lowering 语义标签，是上游维护者自己标注的 | 一条边可能对应多个 pass；边数不等于实现工作量 |
| 边权 | 该目录下的 `.mlir` 测试文件数 | 测试量是工程投入的常用代理 | 测试风格差异会放大/缩小 |
| 文档频次 | 含某方言的测试文件数 | 反映该方言的覆盖面 | 长尾方言被小样本偏置 |
| 方言共现 | 同一文件内同时出现的方言对 | 反映"哪些层绑定在一起" | 文件大小与粒度不均 |
| 收敛度 | 落到 `target` 层的边 / 全部层间边 | 直接测 RQ1 | 受 `layers.json` 归属影响 |
| 成本 \|E\| | 不同的 `(dialect, dialect)` 转换边数 | "每条层间边界实现一次"的成本单位 | 忽略了各边难度差异（见 H3 的折衷） |

**成本模型的推导（要写进正文，不要只放结论）**

设：N 个前端、M 个后端、共享层间的转换边数为 |E|、共享层采纳率为 p。

```
成对适配：  C_pair(N, M)     = N · M
分层共享：  C_layer(N, M, p) = |E| + N + M + (1-p) · N · M
```
第二式的含义：每条层间边界只实现一次（\|E\|），每个前端一个入口（N），每个后端一个出口（M），
但只有比例 p 的前后端对真正走了共享层，剩下 (1-p) 的部分仍需成对实现。

令两式相等，解出交叉点：

```
p·N·M = |E| + N + M   →   N* = (|E| + M) / (p·M − 1)      （仅当 p·M > 1）
```

**这个式子本身就是一条结论**：当 `p·M ≤ 1` 时，分层方案**永远不占优**——无论你加多少个框架。
这就是"条件性收益"的定量形式。

## 3. 参数取值（必须自己核实来源，不许拍脑袋）

| 参数 | 建议取法 | 报告里怎么写 |
|---|---|---|
| \|E\| | 脚本自动实测（`--n-*` 无需填） | "实测得 \|E\| = X" |
| N（前端/框架） | 从 `mlir.llvm.org/users` 里统计"自带前端导入"的项目，或限定为报告讨论的主流框架集 | 明确写出计数口径与被排除项 |
| M（后端/加速器） | 同上，按硬件家族计数（不要把同一厂商的多个型号算成多个 M） | 同上 |
| p（采纳率） | **不要给单点估计**，做 p ∈ {0.4, 0.5, 0.6, 0.8, 1.0} 的敏感性分析 | "本文不假定 p 的具体取值，而报告其敏感性；即使 p=1.0，N\* 仍为……" |

> 这一条很重要：对 p 拍一个数字然后论证，是这篇文章最容易被打的地方。改成敏感性分析，反而显得方法论成熟。

## 6. 威胁效度（照抄进 §6，但要用你自己的话）

1. **代表性**：`mlir/test/` 是上游测试语料，不等于生产使用分布；上游关心的是"转换正确性覆盖"，不是"工业界用量"。
2. **代理偏差**：用测试文件数当"投入"代理，测试风格（TableGen 驱动 vs 手写）会扭曲。
3. **口径偏差**：`builtin`（`module` 等无命名空间算子）、部分 `func` 算子不被计入，导致 `builtin` 被显著低估。
4. **层划分主观性**：见上节的稳健性检验。
5. **\ \|E\| 的语义**：把每条 dialect 转换边视为等成本，忽略了难度差异；因此结论是**结构性**的，不是**绝对成本**的。
6. **只用了一个仓库**：没有覆盖 torch-mlir / IREE 等下游仓库自带的测试语料（若有时间，可作为扩展：把 `--mlir-root` 指向它们则目录结构不同，需另写适配）。
